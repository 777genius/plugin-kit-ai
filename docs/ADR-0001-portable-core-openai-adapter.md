# ADR 0001: Portable core with an OpenAI adapter

Status: accepted on 2026-08-07.

## Context

The Agent Plugins 1.0 open standard requires root `plugin.json`, optional
`mcp.json`, and optional `skills/`. Current OpenAI builder documentation also
describes a host-specific `.codex-plugin/plugin.json`, `.mcp.json`, and repo
marketplace layout.

These files have different schemas and cannot be treated as one manifest.

## Decision

Portable packages under `plugins/` are the source of truth. The OpenAI host
packages under `compat/openai/` and `.agents/plugins/marketplace.json` are
generated by `scripts/build_openai_compat.py`.

Host-only metadata that the portable schema cannot express, such as Codex
OAuth resources or bearer-token environment variable names, is maintained as
an explicit allowlist in that generator and verified against published OpenAI
packages. It must not be guessed for integrations without a published source.

The portable package never contains `.codex-plugin` or `.mcp.json`, so it stays
within the Agent Plugins 1.0 component model. The compatibility package is a
separate distribution artifact.

## Consequences

- Portable manifests are authored once.
- Current OpenAI local marketplace validation is supported.
- Generated adapters must never be edited by hand.
- Public OpenAI directory submission remains a separate review process.
- The adapter can be removed after OpenAI's documented host package matches the
  portable standard and the migration is verified.
